# Paper Parallel 浏览器论文翻译、排版与对照阅读器设计

日期：2026-08-24
状态：待用户审阅

## 1. 背景

现有 P19 页面验证了英文 PDF 解析、分块翻译、基础分页、规则审核和项目包下载等技术点，但它仍是测试运行器：界面包含 mock、阶段日志和调试按钮；中文阅读器展示的是文本卡片，而非真正排版后的 PDF 页面；真实翻译阶段缺少可靠进度、超时和可中断能力；当前排版器也无法继承论文的单栏、双栏、混排、图表与公式结构。

本次工作将重新制作网页，只保留经过验证且仍有价值的底层能力，并建立三个面向最终用户的页面：上传与设置、翻译与排版、双 PDF 对照阅读。

## 2. 目标

1. 用户只需打开 GitHub Pages，不安装 XeLaTeX、Typst、Python 或其他软件。
2. 全部文件处理、翻译协调、Typst 编译和项目缓存均在浏览器中完成；项目不依赖自有服务器。
3. 把英文论文完整翻译为中文，保持内容、技术细节、编号和引用关系。
4. 中文 PDF 继承原论文的版式结构：单栏到单栏、双栏到双栏、混合版式按区域继承，页数自然延伸。
5. 原论文的图、表、公式及其内部内容不得发生任何变化，只翻译图注、表题和相关正文。
6. 生成真正可下载的中文 PDF，并以真实 PDF 页面与英文原文并排阅读。
7. 中英文页数可以不同；正文以句子为最小候选单位、以连续语义组为实际对齐单位，支持拆句与合句；其他内容使用块级或资产级对齐。
8. 翻译过程中提供清晰进度、预计时间、AI 任务日志、超时、重试、安全停止和断点恢复。

## 3. 非目标

1. 不要求中文版与英文版页数相同或元素坐标相同。
2. 不翻译或重绘图内文字、图例、坐标轴、表格单元格、公式或代码。
3. 不承诺首次自动处理任意复杂 PDF 都达到人工出版零误差；低置信度项目必须显式报告，并为以后增加人工修正入口保留数据结构。
4. 不在第一阶段提供多人协作、云端项目存储或后端渲染服务。
5. 不保留 P19 的 mock 演示、探针标题、原始控制台式阶段输出和无文件合成按钮。

## 4. 约束与核心决定

### 4.1 部署

- 前端继续部署在 GitHub Pages。
- Typst 编译器通过 `typst.ts` WebAssembly 在浏览器中运行。
- WASM、固定模板和所需字体使用固定版本并由站点自身托管，避免运行时依赖不可控 CDN。
- 首次使用会下载 WASM 和中文字体；资源通过浏览器缓存和 Service Worker 缓存，后续复用。
- 原始 PDF 不上传到 Paper Parallel 自有服务器。调用 DeepSeek 时只发送待翻译文本块、必要上下文和术语表。

### 4.2 版式继承

“版式相同”指论文结构与排版模式继承，而非像素坐标复制：

- 单栏区域生成单栏中文区域。
- 双栏区域生成双栏中文区域。
- 标题、作者、摘要、关键词、正文、跨栏图表等混合版式按连续区域处理。
- 单栏图表保持单栏属性；跨栏图表保持跨栏属性。
- 标题层级、章节顺序、Section、Figure、Table、Algorithm、Equation 和 Reference 的编号关系保持不变。
- 页眉、页脚、会议标识、arXiv 侧边文字和水印保持原文内容与样式；新增页面按原规则延续。
- 中文自然重排，内容放不下时增加页面，不通过缩小字体强行维持原页数。

### 4.3 不可变资产

- 图片、流程图、图内英文、图例、坐标轴、颜色、线条和箭头为不可变资产。
- 表格主体、单元格、列名关系和数据为不可变资产。
- 数学公式、变量、符号、上下标、希腊字母和公式编号为不可变资产。
- 代码和伪代码内容保持原文。
- 排版器复用从原 PDF 提取或裁切的同一资产，不让生成模型重新绘制。
- 只翻译图题、图注、表题以及正文中的图表引用名称；编号不变。

## 5. 用户体验

### 5.1 上传与设置页

页面由顶部三步导航、PDF 上传区、翻译设置区和论文预览组成。移除旧页面中的三项宣传说明板块。

设置项：

- 英文 PDF 文件。
- DeepSeek API Key，默认仅保存在浏览器；提供显式“存本机”选择。
- 模型选择。连接成功后调用 DeepSeek `/models` 获取当前模型；本设计时的回退列表为 `deepseek-v4-flash` 和 `deepseek-v4-pro`，不使用已弃用的 `deepseek-chat` 或 `deepseek-reasoner`。
- 思考模式独立于模型，通过开关控制。
- 测试连接。
- 高级设置：术语表、补充翻译规则、并发数和重试策略。
- “开始翻译排版”主操作。

核心系统提示词和 JSON 协议不可被普通用户删除。用户只编辑自定义术语表与补充翻译规则，避免破坏保护标记和结构化输出约束。

### 5.2 翻译与排版页

顶部保留：

- 总体进度和当前阶段。
- 已用时间、预计剩余时间。
- 已完成块数和总块数。
- 最近响应时间、成功数、重试数和失败数。
- 安全停止按钮；停止后保留已经完成并通过校验的缓存。

左侧包含两个板块：

1. 任务进度：解析论文、识别版式、建立术语表、翻译正文、生成中文排版、编译 PDF、建立对齐映射、质量检查。
2. AI 日志：显示批次发送、模型、思考模式、响应耗时、token 用量、缓存命中、术语校验、结构校验、重试和错误。日志不得显示 API Key，也不显示模型隐藏思维过程。

主区域显示英文页和正在形成的中文页预览。预览中的图、表和公式仍使用原始资产。

当翻译、编译、映射和质量检查全部通过后，任务状态持久化，并自动跳转到对照阅读页。若质量检查失败，停留在本页并展示可操作的问题，不得显示“完成”。

### 5.3 对照阅读页

- 左侧渲染真实英文 PDF，右侧渲染真实中文 PDF；不是文本卡片。
- 两侧独立显示页码，例如英文 4/8、中文 6/11。
- 支持同步滚动、语句级语义组/段落高亮、点击跳转、缩放和适宽。
- 支持下载中文 PDF 和项目包。
- “返回翻译任务”保留当前任务、日志和缓存。
- “重新选择文件”创建新任务，不隐式删除旧任务缓存。
- “清除翻译缓存”是独立破坏性操作，需要确认后删除当前论文的翻译、术语和排版缓存；原始本地文件不受影响。

## 6. 系统架构

系统按职责拆分为以下模块：

1. `DocumentIngestor`：加载 PDF、生成文件指纹、读取页面与基础元数据。
2. `LayoutAnalyzer`：识别单栏、双栏、全宽和混排区域，生成语义块与原文坐标。
3. `AssetExtractor`：提取或裁切不可变的图、表、公式和代码资产。
4. `TerminologyManager`：根据标题、摘要和章节生成论文级术语表，跟踪首次出现和用户修订。
5. `TranslationCoordinator`：按 token 预算批量发送文本、控制并发、超时、重试、停止和缓存。
6. `TranslationValidator`：校验块 ID、块数、受保护标记、编号、引用、数值和术语一致性。
7. `TypstComposer`：根据版式区域、语义块、不可变资产和翻译文本生成 Typst 项目。
8. `BrowserTypstCompiler`：在 Web Worker 中加载 Typst WASM，编译 PDF，返回进度和错误。
9. `AlignmentBuilder`：建立原文坐标、译文坐标和稳定语义 ID 的映射。
10. `QualityGate`：汇总翻译、版式、资产、编号、坐标和 PDF 可读性检查。
11. `ProjectStore`：使用 IndexedDB 保存任务状态、缓存、术语、PDF Blob 和项目清单。
12. `DualPdfReader`：通过 PDF.js 渲染两份 PDF，执行同步滚动、点击跳转和高亮。

模块之间只传递版本化的项目数据，不依赖页面 DOM 或日志字符串作为状态来源。

## 7. 数据模型

### 7.1 语义单元

```ts
interface SemanticUnit {
  id: string;
  parentId?: string;
  kind: "title" | "author" | "affiliation" | "abstract" |
        "heading" | "paragraph" | "sentence" | "list-item" |
        "caption" | "table-title" | "figure" | "table" |
        "formula" | "code" | "reference" | "page-furniture";
  sourceText?: string;
  translation?: string;
  protectedTokens: string[];
  assetId?: string;
  layoutRegionId: string;
}
```

### 7.2 版式区域

```ts
interface LayoutRegion {
  id: string;
  mode: "single" | "double" | "full-width";
  sourcePage: number;
  bounds: Rect;
  columnGap?: number;
  orderedUnitIds: string[];
}
```

### 7.3 对齐单元

```ts
interface AlignmentUnit {
  id: string;
  kind: "semantic-group" | "block" | "asset" | "reference";
  relation: "1:1" | "1:n" | "n:1" | "n:m" | "paragraph-fallback" |
            "block" | "asset" | "reference";
  sourceUnitIds: string[];
  targetUnitIds: string[];
  source: { page: number; rects: Rect[] };
  target: { page: number; rects: Rect[] };
  confidence: number;
  status: "aligned" | "low-confidence" | "unmatched";
}
```

### 7.4 缓存键

缓存键至少包含：

```text
fileHash + promptVersion + modelId + thinkingMode + glossaryHash + blockId
```

提示词、模型、思考模式或术语表变化时，不得错误复用不兼容结果。

## 8. 通用翻译协议

固定系统提示词不得写死计算机体系结构、密码学、医学或其他学科。它只定义通用学术翻译原则、结构约束、不可变内容和 JSON 输出协议。

每篇论文动态传入：

- 标题、摘要、当前章节和自动识别的领域。
- 论文级术语表。
- 首次出现策略。
- 专有名称处理策略。
- 当前批次及必要的前后文。
- 受保护标记。

模型输出：

```json
{
  "blocks": [
    {
      "block_id": "sec-1-p-03",
      "translation": "……",
      "alignment_groups": [
        {
          "source_sentence_ids": ["sec-1-p-03-s-01", "sec-1-p-03-s-02"],
          "target_segments": ["……", "……"]
        }
      ],
      "new_terms": [],
      "warnings": []
    }
  ]
}
```

模型不决定分栏、分页、字体或图表位置。版式完全由 `TypstComposer` 根据 `LayoutRegion` 处理。正文、列表和图注按完整块翻译；`alignment_groups` 只描述连续源句与连续中文片段之间的语义对应，不要求中英文句数相等。本地代码按返回顺序为中文片段生成稳定目标 ID，并验证所有源句 ID 恰好覆盖一次。

## 9. 对齐设计

### 9.1 粒度

- 正文、列表和图注：先拆成带稳定 ID 的源句候选，但整块送入模型翻译；实际锚点是连续的语句级语义组。
- 语义组支持 `1→1`、`1→N`、`N→1` 和 `N→M`，不得假定英文与中文句法或句数相同。
- 标题和章节标题：块级。
- 图、表和公式：资产级。
- 参考文献：条目级。
- 无法可靠拆句、映射不连续或置信度不足的内容：退回段落级，并记录回退原因。

### 9.2 稳定 ID

语义 ID 在英文解析时生成并贯穿翻译、Typst、PDF 和阅读器，例如：

```text
sec-1-p-03-s-01
fig-1
fig-1-caption
eq-4
```

翻译模型不得改变源句 ID、源句覆盖范围或源句顺序。模型可以按中文语法拆分或合并译文，但只能把连续源句映射到连续中文片段；本地代码为中文片段生成例如 `sec-1-p-03-g-01-t-01` 的稳定目标 ID。

### 9.3 原文坐标

PDF.js 的文字项和页面坐标先聚合为源句或块的矩形片段，再按语义组并集形成原文锚点。图、表和公式使用版式分析器得到的资产区域。一个单元可以包含多个矩形，以表示拆句、合句、换行、跨栏或跨页。

### 9.4 译文坐标

Typst 模板为每个本地生成的中文目标片段写入不可见、带 ID 的定位标记。编译后，`AlignmentBuilder` 读取标记和实际 PDF 文字几何，并按 `alignment_groups` 合并为译文锚点；文字回读结果同时作为校验。拆句、合句、跨行、跨栏或跨页单元均可保存为多个矩形片段。

若标记读取失败，则使用译文字符串与 PDF.js 文字项顺序匹配作为回退。匹配会进行 Unicode 规范化、空白与断行连字符处理，但不会忽略数字、引用或技术符号。

### 9.5 同步滚动

1. 从主动滚动侧的视口中心确定最近对齐单元。
2. 查找另一侧对应矩形，并滚动至相同视觉位置。
3. 长段落内部可在相邻锚点间插值，避免跳跃。
4. 使用来源锁、节流和稳定窗口，防止左右滚动反馈循环。
5. 同步滚动和高亮均可关闭。

未匹配或低置信度单元必须进入质量报告，不得静默标记为成功。

## 10. 任务状态与停止

任务状态使用显式状态机：

```text
idle
→ parsing
→ analyzing-layout
→ building-glossary
→ translating
→ composing
→ compiling
→ aligning
→ validating
→ completed
```

任何运行状态都可以进入 `stopping`，随后进入 `stopped`。错误进入 `failed`，但保留已经通过校验的阶段产物。

- 网络请求由 `AbortController` 控制。
- 每个请求有明确超时。
- Typst 编译运行在 Web Worker；停止时终止 Worker 并保留此前缓存。
- 预计时间根据最近批次吞吐、剩余 token 和编译历史动态计算；数据不足时显示“正在估算”，不显示虚假时间。
- 只有 `QualityGate` 通过后才进入 `completed` 并自动跳转阅读器。

## 11. 错误处理

- API Key 或模型错误：停止新请求，保留缓存，提示重新测试连接。
- CORS 或网络错误：按指数退避重试，日志显示批次和重试次数。
- JSON 无效：进行一次结构修复请求；仍失败则标记该批次，不能伪造结果。
- 受保护标记、数字或引用改变：拒绝缓存该块并重试。
- 术语冲突：进入术语问题列表，允许统一重跑受影响块。
- Typst 编译错误：显示对应语义单元和模板错误，不删除翻译结果。
- 内存不足：释放非当前页画布，降低预览分辨率；仍失败则提供项目包导出以便恢复。
- 对齐失败：保留 PDF，标记未匹配单元；在质量检查中明确显示。

## 12. 安全与隐私

- API Key 不写入项目包、日志、URL、GitHub 仓库或错误遥测。
- 日志中的请求只显示批次 ID、模型、耗时、token、重试和校验摘要。
- 浏览器保存 API Key 必须由用户显式选择，并提供清除入口。
- 下载项目包前再次扫描敏感字段。
- 外部请求域名采用允许列表。
- PDF、翻译结果和缓存默认只存在当前浏览器及用户主动下载的文件中。

## 13. 验证与验收

### 13.1 自动测试

- 版式区域识别：单栏、双栏、全宽和混排样本。
- 术语首次出现和全文一致性。
- 受保护标记、数字、引用、公式编号的完整性。
- 缓存键和提示词版本失效行为。
- 请求超时、重试、停止和恢复。
- Typst 编译、中文字体嵌入和 PDF.js 回读。
- 对齐 ID、跨行矩形、跨页矩形和滚动反馈锁。
- 清除当前任务缓存不会误删其他任务。

### 13.2 视觉验收

使用真实 ZK-Tracer PDF 作为首个端到端样本，并增加不同领域、不同栏型的公开或自有测试文档：

- 标题、作者、摘要、关键词和正文层级正确。
- 单栏到单栏、双栏到双栏、混合区域顺序正确。
- 中文页数可以自然增加，无文字重叠、裁切或越界。
- 图、表和公式与原始资产一致；只翻译允许的标题和图注。
- 页眉、页脚、会议标识、arXiv 文字和水印保持原文。
- 英文和中文真实 PDF 页面可独立缩放、翻页和下载。
- 正文按语句级语义组对齐，图表公式按资产对齐；拆句、合句、低置信度和未匹配项均可见。
- 任务运行时用户始终能判断当前状态、近期活动和预计时间。

### 13.3 完成条件

只有在以下条件同时满足时，网页才显示“处理完成”并自动进入阅读器：

1. 所有必需文本块已翻译或明确标记失败。
2. 不存在未解决的必需块失败。
3. 所有受保护内容校验通过。
4. 中文 PDF 成功编译且能够由 PDF.js 打开。
5. 不可变资产数量和 ID 校验通过。
6. 对齐清单生成完成，低置信度和未匹配项已经报告。
7. 项目状态已写入 IndexedDB，可在刷新后恢复。

## 14. 实施边界

本设计应拆分为连续但可独立验收的实施阶段：

1. 新的三页面壳层、任务状态和缓存模型。
2. 通用翻译协议、术语管理、进度日志、停止和恢复。
3. 版式区域与不可变资产提取。
4. 浏览器 Typst WASM 组合、预览和 PDF 导出。
5. 稳定 ID、坐标清单和双 PDF 阅读器。
6. 真实论文回归、质量门禁和部署迁移。

每个阶段必须保持已有可验证底层能力可回归，但不继续扩展旧 P19 测试 UI 为最终产品页面。
